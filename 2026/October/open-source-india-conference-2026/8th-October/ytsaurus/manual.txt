# Workshop Open Source India

## 1. Prepare Your Environment

### Sign in to the YTsaurus UI

Open the workshop UI:

https://ws.benchmark.ytsaurus.tech

Use the credentials assigned to you:
  - Username: `workshop-user-<YOUR_ID>`
  - Password: `workshop-user-<YOUR_ID>`

For example, participant 1 should use:

- Username: `workshop-user-01`
- Password: `workshop-user-01`

Throughout this guide, `<YOUR_ID>` is your two-digit participant ID, such as `01`, `02`, or `30`.

### Install the YTsaurus CLI

Install the Python client:

```bash
python3 -m pip install --user ytsaurus-client
```

Set your participant ID. Replace XX with your two-digit ID:

```
export MY_ID=XX
```

For example:
```
export MY_ID=01
```

Configure the CLI:

```
export YT_TOKEN="workshop-user-${MY_ID}"
export YT_PROXY="https://http-proxy-ws.benchmark.ytsaurus.tech"
```

Verify that the connection works:

```
yt list //home/workshop
```

> These environment variables apply only to the current terminal session. If you open a new terminal, run the export
> commands again.

### Configure an MCP Client

MCP allows an AI coding assistant to inspect and work with data stored in YTsaurus.

#### Codex

codex mcp add workshop --url https://mcp-ws.benchmark.ytsaurus.tech/mcp

#### Claude Code

claude mcp add --transport http workshop https://mcp-ws.benchmark.ytsaurus.tech/mcp

### Exercise 1: Explore Cypress

Cypress is the hierarchical namespace in which YTsaurus stores tables, files, directories, and other objects.

Open your personal working directory in the UI. Replace XX in the URL with your participant ID:

https://ws.benchmark.ytsaurus.tech/workshop/navigation?path=//home/workshop/userXX

For example:

https://ws.benchmark.ytsaurus.tech/workshop/navigation?path=//home/workshop/user01

List the contents of your directory using the CLI:

```
yt list "//home/workshop/user${MY_ID}"
```

You can also list the workshop root directory:

```
yt list //home/workshop
```

Explore the bronze directory in your workspace:

```
yt list "//home/workshop/user${MY_ID}/bronze"
```

### Exercise 2: Create Your First Table

Open your personal working directory in the UI:

https://ws.benchmark.ytsaurus.tech/workshop/navigation?path=//home/workshop/userXX

Create a static table named: `my_first_table` with columns "key" of type "string" and "value" of type "int64".

Its full Cypress path should be:

//home/workshop/userXX/my_first_table

Or use CLI:

```
yt create table //home/workshop/user${MY_ID}/my_first_table --attributes "{schema=[{name=key;type=string};{name=value;type=int64}]}"
```

Make sure you create the table inside your own directory.

### Exercise 3: Write and Read Data Using the CLI

Write two rows to the table:

```
echo '{"key": "A", "value": 41} {"key": "B", "value": 42}' | \
    yt write-table "//home/workshop/user${MY_ID}/my_first_table" --format json
```

Read the data back:

```
yt read-table "//home/workshop/user${MY_ID}/my_first_table" \
    --format json
```

Now open `my_first_table` in the UI and inspect its contents.

### Exercise 6: Send Train Events to a Queue

Your `bronze` directory contains an ingestion queue:

`//home/workshop/userXX/bronze/trains_queue`

Insert a sample train event into your queue:

```bash
echo '{"event_id":"workshop-seed:train-12192-baq-20261007","ingested_at":"2026-10-07T12:00:00+05:30","train_no":"12192","station_code":"BAQ","payload_json":"{\"arrival\":{\"scheduled_at\":\"2026-10-07T11:30:00+05:30\",\"actual_at\":\"2026-10-07T11:42:00+05:30\",\"delay_min\":12},\"train_name\":\"Jabalpur Express\",\"station_name\":\"Ganj Basoda\"}"}'\
| yt insert-rows "//home/workshop/user${MY_ID}/bronze/queue" --format json
```

Each invocation inserts one event. Run the command several times if you want to produce multiple events:

```bash
for i in {1..5}; do
    echo '{"event_id":"workshop-seed:train-12192-baq-20261007","ingested_at":"2026-10-07T12:00:00+05:30","train_no":"12192","station_code":"BAQ","payload_json":"{\"arrival\":{\"scheduled_at\":\"2026-10-07T11:30:00+05:30\",\"actual_at\":\"2026-10-07T11:42:00+05:30\",\"delay_min\":12},\"train_name\":\"Jabalpur Express\",\"station_name\":\"Ganj Basoda\"}"}' |
      yt insert-rows "//home/workshop/user${MY_ID}/bronze/queue" \
        --format json
done
```

Open the queue in the UI and confirm that the events have appeared:

https://ws.benchmark.ytsaurus.tech/workshop/navigation?path=//home/workshop/userXX/bronze/queue

Replace XX with your participant ID.

This queue is configured with YTsaurus's built-in queue export mechanism. The export is managed by the platform's queue agents—not by an external cron job—and periodically writes newly arrived rows into static tables under:

`//home/workshop/userXX/bronze/trains_raw`

Open this directory in the UI:

https://ws.benchmark.ytsaurus.tech/workshop/navigation?path=//home/workshop/userXX/bronze/trains_raw

Refresh the directory after approximately one minute. A new static table containing the recently inserted events should appear. Exported tables are named using the export timestamp.

## Exercise 9: Build the Gold layer with YQL

  train events with city and weather data.

  Source tables:

  ```text

  //home/workshop/userXX/cities
  //home/workshop/userXX/weather_daily
```

  Destination table:

  //home/workshop/userXX/gold/train_weather

  Ask the agent to inspect all three tables before writing the query. It should identify
  suitable join keys from the actual schemas and data instead of assuming that similarly named
  columns always contain matching values.

  The YQL query should:

  - read the complete Silver train table;
  - associate train events with cities using the available station or location data;
  - join weather observations by city and event date;
  - preserve the train-event grain: one output row per Silver train event;
  - include useful train, city, and weather columns;
  - use LEFT JOIN where appropriate so that unmatched train events are not silently discarded;
  - fully recalculate and replace the Gold table on every run.

  The agent should explain the selected join strategy and show you the query before executing
  it.

## Exercise 11: Explore the relationship between weather and train delays

Use your AI agent to create another dashboard that explores whether train delays are
  associated with weather conditions.

  Source dataset:

  ```text
  //home/workshop/userXX/gold/train_weather
  ```

  Save the dashboard at:

  ```text
  //home/workshop/userXX/dashboards/delay-weather-correlation
  ```

  Ask the agent to inspect the available weather and delay columns before designing the
  analysis.

  Use CHYT for all dashboard data sources and queries. Configure every query source with `engine: "qt"` and `query_engine: "chyt"`. Do not use YQL for dashboard queries.

  The dashboard should include:

  - the correlation between train delay and selected weather measurements;
  - the number of observations used to calculate each correlation;
  - a scatter plot comparing delay with at least one weather measurement;
  - average delay grouped by a relevant weather condition or range;
  - enough context to distinguish missing data from zero values.

  Possible weather measurements include temperature, precipitation, humidity, and wind speed,
  but the agent must use only columns that actually exist in the Gold table.

  The dashboard must clearly state that correlation does not prove causation.
